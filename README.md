# 场记台 · 电影剧本连续性检查工具

使用 React、Vite、TypeScript 和 MUI 从零实现的电影剧本连续性工作台。项目围绕场景、角色、道具、服装、时间线与修订颜色建立真实数据关系，并在场景变化后自动给出可审阅的连续性警告。

## 功能

- 大纲视图、场景详情、资料库与响应式工作区。
- 维护场景、角色、道具、服装、故事时间、拍摄时段、修订颜色和锁定状态。
- **故事顺序与拍摄次序分开维护**：两者都是独立的场次 id 序列，场景资料、连续性警告、审阅结论与作者回复全部以场次身份（稳定 id）关联，挪动拍摄次序不会让首次出场、道具建立或原审阅结论跟错场。
- **拍摄排期批次**：排期调整先进入可单步撤销的批次，确认前不影响当前工作稿；确认时校验为合法排列后写回拍摄次序，并自动保存版本快照（与既有版本并列，可比较、可恢复）；校验失败或取消批次都会保留上一份工作稿继续编辑。
- 自动检查角色无铺垫出现、道具未提前建立、服装与时间冲突、时间线倒退，检查一律按故事顺序进行。
- 审阅人逐条接受或忽略警告，作者可回复并保留修改理由。
- 全文搜索场景名、摘要、地点、故事时间和修改理由。
- 保存不可变版本快照，将历史版本与当前工作稿逐字段（含故事顺序、拍摄次序的位次变化）比较或恢复。
- 撤销重做、自动本地保存和常用键盘操作。
- Service Worker 运行时缓存，已访问的生产页面可离线打开。

## 数据模型与升级

`script.scenes` 只保存场次身份与字段；故事顺序由 `script.storySceneIds` 维护、拍摄次序由 `script.shootSceneIds` 维护。读取本机旧存档（以及历史版本快照中的旧剧本）时会自动按当时的场次数组次序回填两条序列，无需手工迁移。

## 技术栈

- React 18
- Vite 6
- TypeScript
- MUI 6 + Emotion

## 本地开发

```bash
npm install
npm run dev
```

Vite 开发服务器默认使用本地端口 `5174`，该端口不代表容器映射。生产容器仅监听 `80`。

## 生产构建

```bash
npm install
npm run build
npm run preview
```

构建结果位于 `dist/`。

## Docker

```bash
docker build -t sologsb-1017 .
docker run --rm -p 10017:80 sologsb-1017
```

Dockerfile 使用多阶段构建，最终由 nginx 在容器 `80` 端口提供静态文件。宿主端口由根编排文件维护，源码中没有硬编码宿主端口。

## 数据说明

剧本、审查决定、回复和版本快照均保存在浏览器 `localStorage`。应用不调用网络接口，清空站点数据会同时清空本地剧本。
