# 场记台 · 电影剧本连续性检查工具

使用 React、Vite、TypeScript 和 MUI 从零实现的电影剧本连续性工作台。项目围绕场景、角色、道具、服装、时间线与修订颜色建立真实数据关系，并在场景变化后自动给出可审阅的连续性警告。

## 功能

- 大纲视图、场景详情、拍摄排期、资料库与响应式工作区。
- 维护场景、角色、道具、服装、故事时间、拍摄时段、修订颜色和锁定状态。
- **故事顺序与拍摄次序分离**：`scenes` 数组只表示故事顺序（连续性据此推导），`shootOrder` 场次 ID 序列单独表示拍摄次序；剧组挪排期不动故事结构。
- **以场次身份（ID）关联**：角色/道具首次建立场次、服装、警告、审阅结论与作者回复都按 ID 跟随场次，顺序挪动不会串场。
- 旧数据升级时按当前故事次序回填拍摄次序；恢复旧版本快照时同样自动补齐。
- **可撤销的排期批次**：开始调整后挪动只作用于草稿，可逐笔撤销；确认时写回拍摄次序并同时保存一份确认前的既有版本快照；校验失败或取消都会保留上一份已确认的工作稿。
- 自动检查角色无铺垫出现、道具未提前建立、服装与时间冲突、时间线倒退。
- 审阅人逐条接受或忽略警告，作者可回复并保留修改理由。
- 全文搜索场景名、摘要、地点、故事时间和修改理由。
- 保存不可变版本快照，将历史版本与当前工作稿逐字段（含故事顺序、拍摄次序）比较或恢复。
- 撤销重做、自动本地保存和常用键盘操作。
- Service Worker 运行时缓存，已访问的生产页面可离线打开。

## 技术栈

- React 18
- Vite 6
- TypeScript
- MUI 6 + Emotion

## 本地开发

```bash
npm install
npm run dev
```

Vite 开发服务器默认使用本地端口 `5174`，该端口不代表容器映射。生产容器仅监听 `80`。

## 生产构建

```bash
npm install
npm run build
npm run preview
```

构建结果位于 `dist/`。

## Docker

```bash
docker build -t sologsb-1017 .
docker run --rm -p 10017:80 sologsb-1017
```

Dockerfile 使用多阶段构建，最终由 nginx 在容器 `80` 端口提供静态文件。宿主端口由根编排文件维护，源码中没有硬编码宿主端口。

## 数据说明

剧本、审查决定、回复和版本快照均保存在浏览器 `localStorage`。应用不调用网络接口，清空站点数据会同时清空本地剧本。

- `script.scenes`：数组顺序即**故事顺序**，剪辑室据此判断连续性；故事前移/后移只改这里。
- `script.shootOrder`：按**拍摄次序**排列的场次 ID，剧组排期只改这里，与故事顺序互不影响。
- 资料库的「首次建立场景」、警告、回复均通过场次 ID 关联，因此调整任一顺序都不会把结论跟错场。
- 未确认的排期批次保存在 `scheduleDraft`；首次加载旧版本地数据（缺少 `shootOrder`）时，按当前故事次序回填。
